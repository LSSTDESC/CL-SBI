1. configs/simulations/sim_z1_mcmix.json

   Everything else identical to sim_z1.json (Paper-I baseline sim config).

2. configs/inference/infer_z1_mcmix.json
   Byte-identical to infer_z1.json (priors unchanged). Created only so the
   pipeline naming convention {SIM_ID}.{INFER_ID}.{NUM_SIMS}.{NUM_OBS} works
   with a distinct infer_id, per the task spec.

3. scripts/analyze_ftj_mcmix.py
   Post-run analysis. Loads the trained mc-mix FTJ posterior, applies it to
   obs_z1_lambda5 / _ludlow / _prada, collapses the 15-dim percentile MAP
   vector into (mu_M, sig_M, mu_c, sig_c), compares to the old child18-only
   FTJ rows in notebooks/hierarchical_poc_outputs/_all_methods_rows.pkl and to
   truth (mean/std of drawn_mc_pairs columns). Writes
   notebooks/hierarchical_poc_outputs/ftj_mcmix_results.pkl and prints a table.
   NOTE: the percentile->population collapse uses median for mu and
   (P84-P16)/2 for sig, mirroring create_fit_join_observation_nfw /
   _compute_mc_summary. If the main thread confirms Paper I instead reports
   sig as std of posterior samples, adjust percentile_vec_to_population().

FILES MODIFIED
--------------
4. scripts/gen_simulations.py
   In the per-richness-bin loop, added a branch honouring
   sim_config["mc_relation_mix"]. When that list is present, each simulated
   stack (a num_obs-sized chunk = one FTJ training example) is assigned a
   randomly chosen relation from the list before drawing its m-c pairs, so the
   training set spans child18/ludlow16/prada12. When the field is absent the
   original single-relation code path runs unchanged (Paper-I behaviour fully
   preserved). Change is commented "M-C MIX (paper2 apples-to-apples)".
   Verified: the mix branch yields n_stacks_in_bin*num_obs pairs, exactly what
   the downstream slicing loop consumes (range(sims_per_bin // num_obs)), so no
   off-by-one vs the original.
